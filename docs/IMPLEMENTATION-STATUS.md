# Статус исправлений по аудиту

Дата обновления: 28 октября 2026 года.

Обозначения: `готово`, `частично`, `не начато`, `отложено`.

| Finding | Статус | Что сделано | Следующий шаг |
|---|---|---|---|
| F01 — публичное чтение приватных данных | готово | приватный `users` доступен только владельцу; создана очищенная проекция `publicProfiles`; чтение заказов, списка чатов и сообщений выполняется только сервером с проекцией полей и проверкой доступа; отклики закрыты по участникам; используются системные псевдонимы | выполнить отдельную очистку legacy `responses` после проверки production-данных |
| F02 — изменение чужого заказа и доверенных полей | частично | создание и отмена заказа, выбор мастера, основные переходы, версионируемые отклики, отзывы, профиль, заявка на верификацию и сообщения перенесены в серверные команды; физическое удаление заказов запрещено; браузер не может подделать рейтинг или системное уведомление | реализовать административное решение по верификации и будущие изменения заказа только серверными командами |
| F03 — drift rules и частичные записи | частично | завершение заказа и увеличение `completedOrders` выполняются одной серверной транзакцией; согласование условий, mock-оплата, audit events и idempotency receipts также атомарны | перенести оставшиеся legacy-команды и добавить production outbox worker |
| F04 — последние сообщения после 50-го | готово | авторизованный серверный API получает последние 50 сообщений через `desc + limit`, разворачивает их для показа и обновляется polling; прямое чтение чата браузером запрещено | добавить пагинацию старой истории как отдельное улучшение |
| F05 — неправильный маршрут уведомлений | готово | маршрут определяется типом события: чат, отклики, соглашение, трекинг или профиль; чтение и отметка уведомлений перенесены в серверный API с polling вместо зависающей клиентской Firestore-подписки | — |
| F06 — небезопасный Telegram notify endpoint | частично | endpoint fail-closed; клиентский legacy-код создания уведомлений и обращения к внешнему каналу удалён; браузер управляет только чтением | перенести внешние уведомления в server-side outbox/channel adapter |
| F07 — Telegram Mini App | не начато | — | серверная проверка initData и единый identity adapter |
| F08 — уязвимые зависимости | не начато | добавлен `firebase-admin`; слепой `audit fix` не применялся | отдельно обновить Next и проверить достижимость advisory |
| F09 — base64-фото в заказе | отложено | подготовлен и протестирован Firebase Storage adapter с правилами доступа; изменения сохранены отдельно и не включены в production | выбрать S3-совместимое хранилище либо перевести Firebase на Blaze, затем подключить готовый adapter |
| F10 — неатомарный чат | готово | сообщение, preview, unread и уведомление создаются одной серверной транзакцией; список чатов, история и read state обслуживаются сервером; текст восстанавливается при ошибке | добавить пагинацию и outbox для внешних каналов |
| F11 — access/error/loading states | частично | единый auth boundary блокирует защищённые экраны до восстановления сессии; добавлены route-level/global error boundaries и 404; уведомления, чаты, сообщения и список откликов имеют явные loading/error/retry состояния | унифицировать оставшиеся legacy-экраны и подключить внешний error monitoring |
| F12 — отсутствие realtime-обновлений заказа | не начато | — | подписка либо query invalidation после server commands |

## Завершённый фундамент

- ветка `codex/modular-monolith-foundation`;
- чистые domain-правила выбора мастера и переходов заказа;
- Firebase ID token проверяется на сервере;
- Firestore Admin используется только в server-only adapter;
- выбор мастера атомарно пишет заказ, аудит, уведомление и receipt;
- переходы `start_work`, `mark_ready`, `confirm_delivery` выполняются сервером;
- повтор команды защищён `commandId`;
- публичный псевдоним генерируется без реального имени;
- Firestore rules запрещают браузеру менять доверенные поля заказа;
- standalone build и Dockerfile;
- описан путь Firestore → PostgreSQL и Storage → S3;
- закрытые отклики вынесены в `orders/{orderId}/proposals/{masterId}`;
- заказчик видит все отклики, мастер — только собственный;
- новая версия отклика не уничтожает историю, актуальность истекает через 3 дня;
- чат доступен только участникам, контакты до оплаты блокируются без запрета обычных мерок;
- прямое раскрытие Telegram ID мастера из интерфейса удалено;
- приватный профиль и публичная проекция разделены; социальные сети и документы в публичную проекцию не попадают;
- роль, статистика, верификация и Telegram ID изменяются только серверными командами;
- создание заказа идемпотентно и атомарно пишет заказ, аудит, receipt и outbox event;
- лента и карточки заказов загружаются через серверный API, прямое чтение `orders` запрещено;
- выдача мастеру учитывает категории, город, верификацию и разрешение доставки;
- новые заказы обязательно содержат название, мерки, город и способ получения;
- пользовательское портфолио удалено из профиля: публичный опыт будет строиться из выполненных заказов платформы;
- полный `eslint`, TypeScript и production build проходят без ошибок;
- 66 domain/config-тестов и 13 emulator-тестов правил доступа.
- отзывы обеих сторон вынесены в отдельную серверную сущность; повторная отправка и утечка оценки до 7-дневной даты публикации запрещены.
- после выбора мастера обе стороны согласуют версионируемый снимок цены, срока, мерок, доставки и допустимых отклонений;
- новая версия условий сбрасывает оба подтверждения, а переход к оплате происходит только после независимого подтверждения заказчиком и мастером;
- добавлен тестовый платёжный контур без списания денег: сумма хранится в копейках, комиссия закрытой беты зафиксирована на 10%, операции и ledger-события идемпотентны;
- для новых заказов мастер может начать работу только после подтверждённой тестовой оплаты; legacy-заказы остаются совместимы со старым сценарием;
- список откликов мастера использует collection-group индекс по `proposals.masterId`; ошибка чтения больше не маскируется пустым состоянием;
- карточка участника заказа зависит от роли: заказчик видит мастера, мастер — системный псевдоним заказчика;
- интерактивная оценка реализована семантическими кнопками и доступна с клавиатуры и для скринридеров;
- HTML-ответ защитной проверки Vercel и другие некорректные ответы сервера показывают понятную причину и безопасное действие вместо общей ошибки;
- физическое удаление заказа заменено на идемпотентную серверную отмену со статусом, аудитом, receipt и outbox-событием; после выбора мастера интерфейс направляет процесс в будущий контур поддержки;
- GitHub Actions выполняет lint, TypeScript, domain/config-тесты, emulator-тесты правил Firestore и production build на push и pull request;
- media adapter не развёрнут: Firebase Storage для этого проекта требует подключения платного тарифа, а внешние платные действия до готовности продукта не выполняются.
